# 数据库与数据

项目数据存放在 **Cloudflare D1**（SQLite）数据库中，通过 Drizzle ORM 访问。本文档涵盖表结构、迁移操作，以及线上数据的导出 / 导入。

---

## 1. 数据库概览

| 项 | 值 |
| :--- | :--- |
| 数据库绑定名（binding） | `DB` |
| 数据库名称（database_name） | `steamsda-api` |
| 数据库 ID（database_id） | `234e2906-f23d-4ab9-8fae-184ebbe6e742` |
| 迁移目录 | `./migrations` |
| 配置位置 | `wrangler.jsonc` 的 `d1_databases` |

> 说明：D1 底层就是 SQLite，因此所有数据都能以标准 SQL 形式整库导出 / 导入。

---

## 2. 数据表

表结构统一定义在 `db/schema.ts`（Drizzle schema）：

| 模型 | 表名 | 说明 |
| :--- | :--- | :--- |
| `user` | `User` | 用户账号 |
| `allProduct` | `AllProduct` | 全部可订阅产品目录 |
| `product` | `Product` | 当前账号已开通的订阅 |
| `machineBinding` | `MachineBinding` | 机器码与账号的绑定关系 |
| `categories` | `categories` | 游戏分类（含 `slug`、启用标记） |
| `platforms` | `platforms` | 游戏平台（含 `slug`） |
| `games` | `games` | 游戏库（含 `categoryId`、`platformId`、`sort`、`isHot` 等） |

`games` 通过 `gamesRelations` 关联到 `categories`，详情页查询可用 `with:{category:true}` 直接带上分类。

> ⚠️ `categories` / `platforms` 的 `slug` 字段会被用于动态路由（`/categories/[slug]`、`/platforms/[name]`），
> **必须是 URL 友好格式**（小写 + 连字符，不能有空格 / 单引号 / 斜杠），否则访问会 404。
> 历史上 `Shoot 'em up`、`Beat 'em up` 曾因特殊字符导致 404，已修正为 `shoot-em-up`、`beat-em-up`。

统一通过 `GET /api/me` 返回 `{ me, allProducts, products }`。

## 3. 迁移操作（drizzle-kit）

```bash
# 根据 db/schema.ts 生成迁移文件到 ./migrations
npx drizzle-kit generate

# 应用迁移到线上 D1（走 drizzle.config.ts 的 d1-http 驱动）
npx drizzle-kit migrate
```

`drizzle-kit migrate` 依赖本地 `.env` 中的 `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_DATABASE_ID`、`CLOUDFLARE_D1_TOKEN`（见 [环境配置](./环境配置.md)）。

## 4. 登录 Cloudflare

导出**线上**库必须拥有该 Cloudflare 账号的权限。两种登录方式任选其一。

### 方式 A：浏览器 OAuth 登录（推荐本地开发）
```bash
npx wrangler login
```
执行后会在浏览器打开授权页，登录并授权即可。登录态会缓存在本机，后续命令无需重复登录。

### 方式 B：API Token（适合 CI / 无浏览器环境）
```bash
# 在 Cloudflare 控制台「My Profile → API Tokens」创建一个具备
# Account → D1 权限的 Token，然后在本机设置环境变量：
export CLOUDFLARE_API_TOKEN=xxxxxx

# （可选）指定账号 ID
export CLOUDFLARE_ACCOUNT_ID=yyyyyy
```
> 注意：`CLOUDFLARE_API_TOKEN` 属于敏感凭证，不要写进仓库或提交到 git。

## 5. 导出线上数据到本地

所有导出命令均在项目根目录 `steam-web-api/` 下执行。

### 5.1 整库导出为 SQL 文件（最常用，可作备份 / 迁移）

```bash
mkdir -p backup
npx wrangler d1 export DB --remote --output ./backup/steamsda-api-$(date +%F).sql
```

- `DB`：wrangler.jsonc 里的绑定名。
- `--remote`：**导出线上库**；去掉该参数则导出本地库。
- 产物是标准 SQLite SQL（含 `CREATE TABLE` + `INSERT`），可用以下工具直接查看：
  - DB Browser for SQLite（图形界面）
  - DataGrip / DBeaver
  - 命令行 `sqlite3`：`sqlite3 local.db < dump.sql`

### 5.2 导出到本地 D1，供本地开发联调

如果你想把线上数据搬过来跑 `npm run dev`：

```bash
# 1) 先导出整库（见 5.1）
npx wrangler d1 export DB --remote --output ./backup/steamsda-api.sql

# 2) 导入进本地 D1（本地库默认无表，执行 dump 会同时建表 + 灌数据）
npx wrangler d1 execute DB --local --file ./backup/steamsda-api.sql
```

⚠️ **注意事项**：如果本地 D1 已经通过 `migrations` 建过表，再执行 dump 里的 `CREATE TABLE` 会报 `table already exists`。解决二选一：
- 用全新本地库：删除 `.wrangler/state/v3/d1/` 下对应文件后再执行导入；或
- 只导出数据部分，见 5.3。

### 5.3 只导出部分表 / 转 CSV

```bash
# 单表直接查询导出（用 SQLite 的 CSV 模式）
npx wrangler d1 execute DB --remote \
  --command ".mode csv" \
  --command "SELECT * FROM product;"
```

或者先按 5.1 导整库 SQL，再自行裁剪需要的表，然后：

```bash
sqlite3 local.db < dump.sql          # 导入到普通 sqlite 文件慢慢筛选
```

## 7. 常见问题

- **`wrangler` 提示未登录 / 权限不足**：先执行 `npx wrangler login`，确认账号对该 D1 数据库有访问权限。
- **导出报 `table already exists`**：本地库已有表结构，按 5.2 的注意事项清理本地库或只导数据。
- **导入本地 D1 报 `foreign key mismatch - "Product" referencing "User"`**：`wrangler d1 export` 会把唯一索引（如 `User_userId_unique`）排在带外键的子表（如 `Product`、`MachineBinding`）**之后**，SQLite 建子表时校验父表被引用列是否唯一，此时索引尚未建立便报错。修复办法：把 `CREATE UNIQUE INDEX ... ON User(userId)` 移到 `User` 表之后、`Product`/`MachineBinding` 表之前再导入。线上库本身无此问题（迁移时索引先建好）。
- **分类 / 平台详情页 404**：多为 `slug` 含空格、单引号等特殊字符，见第 2 节说明，修正 DB 中的 slug 即可。
- **`--remote` 连不上 / 超时**：检查网络能否访问 `api.cloudflare.com`，以及是否配置了正确的 `CLOUDFLARE_ACCOUNT_ID`。
- **导出的 SQL 在哪个目录**：默认在项目根下的 `backup/`（需先 `mkdir -p backup`）。

## 8. 安全提示

- `wrangler.jsonc` 中的 `AUTH_SECRET`、`RESEND_API_KEY` 等属于敏感信息，线上请改用 `wrangler secret put` 管理，不要明文提交。
- 导出的数据库 dump 可能包含用户数据，请妥善保管，不要上传到公开仓库。
